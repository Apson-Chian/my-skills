# 玻璃材质界面

把玻璃做成能透出实际背景、有合理光学层次且保持内容清楚的界面材质。直接在用户现有技术栈和组件上实现；审查请求则提供有画面证据的问题与修改建议。

## 使用顺序

1. 先看实际页面、现有材质组件、主题与背景来源。辨别问题来自底色、模糊、采样、折射还是层级，避免只调一个 blur 数值。
2. 确认玻璃的用途：浮动导航、工具条、小按钮、数据卡片、输入区或弹层。不同用途共享照明与色调，透明度、模糊和阴影按内容密度与浮起程度调整。
3. Web 读取 [Web 实现](references/web.md)；Android 读取 [Android 实现](references/android.md)。只加载当前平台需要的说明。其他原生平台沿用工程现有材质能力，先核实对应 API，不能照搬 CSS 或 Android 实现。
4. 修改后按下面的可观察结果验证，展示代表性截图，说明实际采用的是模糊、近似折射还是真实背景位移，以及已验证的环境。

用户已给出目标画面或平台参照时沿用它。当前个人 Web 液态玻璃默认已更新为 2026-11-13 确认的通透版本：折射 72%、背景模糊 8%、压感 80%，详见 [当前参数](references/liquid-glass-current.md)。新要求优先；Android 使用自身渲染能力，不照搬 Web shader 的 UI 刻度。更早的 LifeRecord 案例见 [偏好与案例](references/preferences.md)。旧项目的发布、部署授权不随 skill 复用。

## 材质标准

### 透明与底色

- 默认追求轻盈、通透，避免厚白底、大片糖果色和抢眼的整圈描边；这些是个人默认取向，可由具体设计覆盖。
- 背景需要有可辨认的内容变化。平坦背景上效果不明显时先检查采样，不为展示玻璃擅自替换整站背景。
- 浮动控件允许更多透射；密集数据和表单需要更稳定的阅读底色。深浅主题分别调参，不能只反转文字颜色。
- 前景文字、图标、焦点和表单内容保持清晰。通过材质底色保证最不利背景下的对比度，不通过降低整个组件的 opacity 获取透明。

### 折射

- 明确区分：模糊降低细节；折射改变背景像素的位置。渐变、内阴影、复制静态图片和整体缩放不能证明实际页面背景被折射。
- 需要液态折射时，优先保持中心稳定，让圆角边缘产生克制的位移或放大。强度随尺寸和背景调整，不能以扭曲文字制造“高级感”。
- 使用真实背景输入的渲染路径；没有可靠输入或目标环境不支持时采用清晰的近似或无折射回退，并如实说明。不能静默把回退当成真实折射完成。
- 当前 Web 默认在窄边缘保留轻微彩色折光，按住时适度增强；不做浓重彩虹描边或整面染色。模糊独立可调，只影响背景，前景文字和图标保持清晰。

### 高光与阴影

- 默认统一左上方照明：薄而柔和的亮边、少量面光和对侧暗部共同建立厚度；光照方向是可调整的设计起点。
- 面光放在前景下方，顶部细边可以覆盖材质，均不影响点击。避免全白硬描边、强烈彩虹边和常驻扫光，除非用户明确要求。
- 宽而轻的环境阴影配合短接触阴影。弹层和浮动导航比普通卡片更浮起；阴影不能代替透射或真实模糊。

### 渐进模糊

- 导航或工具条与内容交界处从清晰平滑过渡到模糊，模糊的是其后的内容，前景导航文字和图标单独绘制。
- 透明渐变遮罩只改变可见度，不能独自实现空间变化的模糊半径。多档模糊加蒙版融合属于近似，需观察是否出现条带、重影与硬接缝。
- 覆盖实际遮挡宽度和系统安全区域；预留内容滚动到底的空间。键盘、导航隐藏或弹层移动时，模糊层同步更新，不能留下悬空色块。

## 渲染约束

- 明确单向关系：背景源 → 材质效果 → 清晰前景。自定义背景捕获排除使用该源的玻璃层、导航、弹窗和装饰，避免递归采样。内嵌卡片可只采环境，浮动导航与弹窗按需采页面内容。
- 滚动、主题切换、源内容更新、窗口变化和弹层拖动后，采样与屏幕位置一致。模糊与位移先预留采样边界，再裁切最终外形。
- 优先复用共享材质与平台渲染能力；确有缺口再引入依赖。不要为视觉效果默认执行 CPU 每帧截图、重复编译 shader 或创建永不停止的动画循环。
- 性能退化时依次减少有效滤镜面积、重叠层数、采样分辨率和光学复杂度，保留清晰前景、层级与可用交互。静态页面不需要持续刷新。
- 支持减少透明、增加对比和减少动态效果的设置；不能读取系统偏好的平台，沿用项目已有的外观或性能选项。无需为一次局部修复新建整套设置页。
- 浮动分段导航需要液态交互时支持按住拖动：选中玻璃连续跟手、跨中线切换栏目、松手贴合，并保留点击和键盘。若同时有 `liquid-glass-controls`，可复用其控件实现；当前参数参考本 skill 自带文件即可读取。

## 验收：看效果与行为

根据改动范围选择相关场景，不把每次调色扩展成全项目审查。

| 场景 | 需要看到的结果 |
| --- | --- |
| 彩色条纹、细线或棋盘格在材质后方移动 | 模糊能降低背景细节；若声称折射，边缘特征位置确实改变，中心相对稳定 |
| 替换背景或滚动后再次进入页面 | 材质随背景更新，没有首次进入时的一小块残影、旧色块或错位 |
| 导航交界处缓慢滚动 | 清晰到模糊连续过渡，没有硬边、拉伸边缘或重复文字；导航图标清晰 |
| 明暗主题、照片背景与密集文字 | 标题、正文、输入内容、焦点与禁用态可辨认，没有叠加后发灰或过曝 |
| 打开、拖动、关闭弹层与弹出键盘 | 效果跟随真实内容层，无遮挡误触，关闭后不残留滤镜，底部操作仍可到达 |
| 关闭效果或触发降级 | 阅读底色与边界仍成立，交互不变，昂贵采样确实停止 |

在实际页面或临时隔离夹具中检查；实现自定义采样、折射或缓存修复时，增加能复现问题的像素/交互回归。普通视觉微调以实际截图和操作检查为主，不编写只匹配样式字符串的测试。

构建成功、shader 编译成功和像素位置变化分别证明不同事情。模拟器与浏览器截图不能证明其他设备的流畅度；性能结论需要对应设备的测量证据。无法运行的场景明确标为未验证。
