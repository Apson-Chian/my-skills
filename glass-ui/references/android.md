# Android 玻璃实现

这些建议提炼自 LifeRecord 的实际问题；适配当前工程的 SDK、Compose/View 版本与渲染结构，不能假定存在同名组件，也不能照搬旧工程的设备测试结果。

## 能力分级

| 环境 | 优先方案 | 需要说明的边界 |
| --- | --- | --- |
| Android 13 / API 33 及以上 | 有背景输入的 `RuntimeShader` / AGSL，可按需叠加原生模糊 | shader 编译成功仍需验证实际位移、输入更新与 GPU 差异 |
| Android 12 / API 31–32 | `RenderEffect` 背景模糊；需要时用镜片带等办法近似边缘放大 | 不具备 RuntimeShader；近似效果不能报告成同一 shader 实现 |
| 旧版本、效果关闭或性能不足 | 清晰底色、细边和轻阴影 | 关闭昂贵背景采样，保留交互与阅读层次 |

AGSL 的平台起点见 [Android AGSL](https://developer.android.com/develop/ui/views/graphics/agsl)；模糊 API 见 [RenderEffect](https://developer.android.com/reference/android/graphics/RenderEffect)。具体依赖与 API 可用性以工程当前版本核实，不为材质默认升级整套 Compose。

## 背景输入

`RenderEffect` 或 Compose blur 作用于所属渲染节点，不会自动获得任意兄弟节点背后的画面。先确定哪个层记录背景，再把输入送进材质。需要文字保持清晰时，不要把前景一起录进去。

内嵌数据卡片可采环境背景；浮动导航、输入条与弹窗按需采完整页面内容。捕获区域排除使用该源的效果层。优先复用工程已有 GraphicsLayer 或等效录制机制，而不是每帧 CPU 截图回读。

低分辨率只用于光学输入，文字和原页面维持正常分辨率。可从半分辨率折射、四分之一分辨率大范围模糊开始试调，实际清晰度和开销决定最终值，不能作为全机型固定参数。

## 渐进模糊与采样边界

可把同一背景输入的少量不同模糊半径按纵向权重融合，作为渐进模糊近似。避开多层重采样造成的成本和重复轮廓。

在源中预留模糊核与折射位移的边界，再裁切最终圆角区域；只把一行边缘像素拉长会形成条纹。根坐标、局部坐标、density、窗口位置和系统导航 inset 都需统一换算。

## 残影、弹窗和生命周期

如果只在刚进入时出现一小块模糊并一直残留，检查源是否重录、输入绑定是否更新、尺寸是否仍是初次布局值，以及节点复用后的失效传播。不要用更浓遮罩把残影盖掉。

跨窗口弹窗先对齐屏幕坐标，再核查页面状态变化是否更新了弹窗使用的滤镜输入。源节点与目标节点可能都需要失效；复用编译后的 shader，更新输入与 uniform 即可，避免每次绘制重新编译。

把弹层玻璃放进实际移动的内容层。检查半展开、展开和关闭过程中裁切、阴影及点击命中是否一起移动。键盘出现时按产品现有行为隐藏或移动导航及其渐进层，不残留装饰；装饰自身不消费触摸。

节点销毁、窗口关闭或页面离开时解除观察者与回调，释放不再使用的图层和缓冲；不能用常驻定时刷新掩盖缓存失效错误。

## 有价值的回归

- 将移动彩条/细线放到生产材质背后，验证边缘位移、中心稳定与源更新后的画面变化。
- 对有 API 分支的实现分别运行对应系统镜像；尤其检查 API 31 的输入刷新、跨窗口和重进页面。API 35 上运行近似算法不能替代 API 31 系统验收。
- 断言实际命中的渲染路径，例如 AGSL 是否成功启用；降级也单独验证。不能让静默 fallback 使高级路径测试假通过。
- 大字体、明暗主题、键盘和弹层拖动需要验证实际可见区域与可点击区域，避免只断言节点存在。
- 需要设备测试时使用工程已有的隔离包与合成数据，避免影响用户正在使用的应用。

历史上 vivo Android 15 与真我 Android 12 出现不同表现。记录具体系统与设备；没有对应真机时仅报告已检查的模拟器范围，不能推断其帧率、温升或 OEM GPU 行为。
